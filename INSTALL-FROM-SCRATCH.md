# Установка сервиса штрафов с нуля

Пакет `LUZHNIKI-FINES-SERVER-V54.2-FULL` является полной
сборкой, а не обновлением. Установщик прекращает работу, если целевой каталог
уже существует.

Архив приватный: внутри находится рабочий файл `.env`. Не публикуйте архив и
не пересылайте его в открытые каналы.

## 1. Загрузка и распаковка

Скопируйте ZIP в `/root`, затем выполните:

```bash
cd /root
sha256sum LUZHNIKI-FINES-SERVER-V54.2-FULL-2026-10-12.zip
unzip -n LUZHNIKI-FINES-SERVER-V54.2-FULL-2026-10-12.zip -d /root
cd /root/LUZHNIKI-FINES-SERVER-V54.2-FULL
sha256sum -c SHA256SUMS.txt
```

Сверьте хеш ZIP с файлом `.sha256.txt`, переданным рядом с архивом.

## 2. Проверка без изменений

```bash
bash 00-check-read-only.sh
```

Проверка не пишет данные в Bitrix. Она контролирует:

- доступ к Bitrix и платёжному сервису;
- разрешённые карточки 4651, 4652, 4653 и 4750;
- актуальное непустое название каждой карточки;
- тип «услуга» и включённый НДС 22%;
- рабочую платёжную систему ID 24;
- отсутствие второй активной кнопки ЮKassa/СБП ID 30.
- одинаковый полный платёжный маршрут для товара 4750 на 10 ₽ и боевых услуг.

## 3. Чистая установка

```bash
bash 01-install-fresh.sh
bash 02-status-read-only.sh
```

Скрипт устанавливает отдельный systemd-сервис и конфигурацию Nginx. Он не
выполняет обновление существующей установки.

## 4. Защита оплаты и чека на сервере Bitrix

Установите обработчик из каталога:

```bash
cd /root/LUZHNIKI-FINES-SERVER-V54.2-FULL/server/bitrix
bash 00-check-read-only.sh
bash 01-install-handler.sh
bash 02-status-read-only.sh
```

Подключается один локальный обработчик Bitrix. Он не заменяет ядро, сайт или
обработчик Сбербанка. Для штрафов платёжной системы ID 24 он блокирует повторный
переход `PAID=N → Y` при одновременных callback, поэтому на один платёж в очередь
может быть поставлен только один фискальный чек.

## 5. Контрольная оплата

После установки проведите одну контрольную оплату и проверьте:

1. На платёжной странице отображается одна кнопка оплаты.
2. В заказе и чеке находится текущее название из карточки товара Bitrix.
3. Предмет расчёта — услуга, НДС — 22% и включён в цену.
4. В заказ записаны email и телефон клиента.
5. Сделка создана, связана с правильным контактом и перешла по нужным стадиям.
   В карточке контакта заполнены имя, фамилия, телефон и email.
6. Ссылка на чек доступна в Bitrix, а ОФД отправил чек на email клиента.
7. В заказе создан ровно один чек; повторное открытие страницы успеха и повторный
   callback не создают второй чек.

## Отключение с сохранением файлов

```bash
cd /root/LUZHNIKI-FINES-SERVER-V54.2-FULL
bash 03-disable-and-preserve.sh
```
