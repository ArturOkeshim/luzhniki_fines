# Как безопасно изменить стоимость штрафа

## Откуда берётся сумма

В V54.2 веб-сервер не назначает стоимость штрафа самостоятельно. Для каждой
оплаты он сверяет одновременно:

1. сумму карточки штрафа в смарт-процессе Bitrix;
2. цену и количество в товарной строке этой карточки;
3. итоговую сумму создаваемого заказа и платежа;
4. допустимость номинала в серверном коде.

Цена карточки товара каталога используется для настройки и работы операторов,
а её название, тип «услуга» и НДС 22% сервер перечитывает перед каждой новой
оплатой. У уже созданной карточки штрафа товарная строка может сохранять старую
цену даже после изменения цены каталожной карточки.

Если суммы карточки штрафа и её товарной строки отличаются, платёжная ссылка не
выдаётся. Это защита от неверного чека.

## Смена на уже разрешённый номинал

В V54.2 разрешены суммы 10, 5 000, 10 000 и 25 000 ₽. Для перехода между ними
код веб-сервера менять не требуется.

В Bitrix в одной и той же карточке штрафа необходимо:

1. изменить поле «Сумма штрафа» и поле суммы сделки на один номинал;
2. открыть вкладку «Товары»;
3. выбрать соответствующую каталожную услугу;
4. установить цену товарной строки равной сумме штрафа, количество — 1;
5. сохранить карточку;
6. убедиться, что карточка находится в неоплаченной стадии направления
   «Штрафы».

Для тестового штрафа 10 ₽ используется товар 4750 «тест 10». У него должны
оставаться тип «услуга», активная ставка НДС 22% и признак включения НДС в цену.

После сохранения выполните на сервере сайта проверку только на чтение:

```bash
cd /opt/luzhniki-oplata-shtrafov/shtrafiParkovrf

curl --fail --silent --show-error --get \
  'http://127.0.0.1:3000/api/fines' \
  --data-urlencode 'plate=ГОСНОМЕР' |
  /usr/bin/node -e '
    let input = "";
    process.stdin.on("data", (chunk) => input += chunk);
    process.stdin.on("end", () => {
      const data = JSON.parse(input);
      const fines = (data.fines || []).map(({id, name, amount}) => ({id, name, amount}));
      console.log(JSON.stringify({plate: data.plate, total: data.total, fines}, null, 2));
    });
  '
```

В ответе должны быть новая сумма штрафа и такой же `total`. Команда ничего не
изменяет. После этого проверяется экран сайта. Создание реального платежа и чека
выполняется только отдельной согласованной контрольной оплатой.

## Добавление нового номинала

Сумма, отличная от 10, 5 000, 10 000 и 25 000 ₽, текущей V54.2 будет отклонена.
Одного изменения `.env`, карточки товара или базы данных недостаточно.

Для нового номинала требуется новая версия проекта, в которой:

- номинал добавлен в `ALLOWED_FINE_AMOUNTS` файла `app/lib/fines.ts`;
- при использовании списочного поля Bitrix добавлено соответствие ID варианта
  и суммы в `FINE_AMOUNT_ENUM_VALUES`;
- подготовлена или разрешена правильная карточка каталога в
  `B24_FINE_PRODUCT_IDS`;
- добавлены тесты нового номинала;
- повторно проверены услуга, НДС 22%, включение НДС в цену, покупатель и
  фискальная корзина;
- выполнены `npm test`, production-сборка и read-only preflight.

Ручное редактирование собранного `dist` запрещено: такая правка не
воспроизводится и может исчезнуть при следующей установке. Новый номинал следует
выпускать отдельным архивом с SHA256 и возможностью возврата к предыдущей
версии.

## Проверка действующей службы

```bash
systemctl is-active luzhniki-fines
systemctl is-enabled luzhniki-fines
curl --fail --silent --show-error --output /dev/null \
  http://127.0.0.1:3000/
journalctl -u luzhniki-fines -n 50 --no-pager
```

Изменение суммы не требует удаления старых заказов, платежей или чеков. Уже
созданный платёж переписывать нельзя: для другой суммы создаётся новая
неоплаченная карточка/платёж после проверки исходных данных.
